# КОЛЕКЦИОНЕРСКИ СВЯТ. — мениджър на колекции

Учебен проект по интернет програмиране, 12. клас · тема 2 · Борис

Приложението помага на колекционерите да описват предметите си, да предлагат размяна, да участват в търгове и да разговарят помежду си. Визията и имената следват стария „Collection Manager“, а жизненият цикъл е съобразен с приложеното задание за тема 2.

## Изисквания и технологии

- ASP.NET Core 8 Web API и чист HTML, CSS и JavaScript в един проект и един origin. Solution файлът е `CollectionManager.sln` и се отваря директно във Visual Studio.
- PostgreSQL, ADO.NET и Npgsql. Транзакционните правила за размяна, търгове и наддавания са в услугите и използват заключвания в PostgreSQL.
- JWT с роля `Collector`, `Evaluator` или `Admin`. Ролята се взема от подписания токен.
- Седем таблици: `Users`, `Categories`, `Items`, `TradeOffers`, `Bids`, `Messages` и `Notifications`.
- Две PostgreSQL изгледни заявки: `vw_AuctionLeaders` и `vw_CollectionInventory`. Схемата и категориите се създават автоматично при първо стартиране.

Това е ASP.NET Core API по актуалното задание. В стария чат първоначалната идея беше наречена ASP.NET MVC; заданието в DOCX задава API, JWT и статичен JavaScript front-end, затова реализацията следва документа.

## Потребителски роли

| Роля | Достъп |
| --- | --- |
| Колекционер (`Collector`) | Управлява собствените предмети, предлага/приема размяна, наддава и пише съобщения. |
| Оценител (`Evaluator`) | Вижда предметите `PendingApproval` и одобрява или връща заявка за търг. |
| Администратор (`Admin`) | Управлява категориите и обработва изтеклите търгове. Създава се само от началните SQL данни. |

## Жизнен цикъл

Предметът преминава през следните състояния:

```text
InCollection → ForTrade → Traded
InCollection → PendingApproval → OnAuction → Sold
                                      └──── без наддавания → InCollection
```

Размяна е възможна за чужд предмет `ForTrade` срещу собствен предмет `InCollection`. Само получателят — текущият собственик на желания предмет — може да я приеме. `TradeService.AcceptTrade` заключва предложението и двата предмета в една транзакция, сменя собствениците и отказва другите чакащи предложения, които използват същите предмети.

Търгът се отваря след одобрение от оценител и продължава седем дни. Наддаване е разрешено само преди крайния час и само от колекционер, който не притежава предмета. `TradeService.CloseDueAuctions` в една транзакция прехвърля предмета на най-високия наддавач или го връща в `InCollection`, ако няма наддавания. Администраторът стартира обработката от панела.

## Собствено бизнес правило на Борис

Всяко ново наддаване трябва да е поне с 5% по-високо от най-високото до момента, а първото е минимум 0,52 €. Интерфейсът и API работят в евро. За да запазят стойността на вече записаните оферти, старите стойности в базата се конвертират по фиксирания курс 1 € = 1,95583 лв. Правилото е в `TradeService.PlaceBid`: транзакцията заключва реда на предмета, така че едновременните наддавания да се обработят последователно. Например при текущи 100 € системата приема 105 € и отказва 104,99 € с HTTP 409.

## Скрити данни и права

Телефонът и адресът за доставка не се включват в списъка с предмети. Подробностите ги връщат само след приключена размяна за нейните участници или след продажба за спечелилия търга. API прилага ограничението; скрит бутон в браузъра не се използва като защита. Всеки разговор се чете само от двамата му участници. Регистрацията има отделни адреси за колекционер и оценител; няма endpoint за регистрация на администратор.

## Стартиране

1. Инсталирай PostgreSQL за Windows от [официалната страница за изтегляне](https://www.postgresql.org/download/windows/). Запомни локалната парола за потребителя `postgres` и остави стандартния порт `5432`.
2. В PowerShell задай локалната връзка (замени `ТВОЯТА_ЛОКАЛНА_ПАРОЛА` с паролата, която избра при инсталацията):

   ```powershell
   $env:ConnectionStrings__CollectionDb = "Host=localhost;Port=5432;Database=collection_manager;Username=postgres;Password=ТВОЯТА_ЛОКАЛНА_ПАРОЛА"
   $env:Jwt__SigningKey = "local-development-key-change-before-deploy-123456"
   ```

3. Отвори [CollectionManager.sln](CollectionManager.sln) във Visual Studio и стартирай профила `CollectionManager.Api` с F5. Или отвори PowerShell в папката на проекта и стартирай:

   ```powershell
   $env:DOTNET_CLI_HOME = Join-Path $PWD '.dotnet'
   $env:NUGET_PACKAGES = Join-Path $PWD '.nuget\packages'
   dotnet restore .\CollectionManager.Api\CollectionManager.Api.csproj -p:NuGetAudit=false
   dotnet run --no-restore --project .\CollectionManager.Api\CollectionManager.Api.csproj
   ```

4. При стартиране приложението създава PostgreSQL схемата, изгледите и категориите, ако липсват. За незадължителни демо профили и предмети изпълни `CollectionManager.Api/SQL/03_Seed.sql` веднъж през pgAdmin Query Tool.
5. API и front-end се обслужват от един адрес; Swagger UI е на `/swagger` (профилът във Visual Studio отваря `http://localhost:5186`). В Swagger натисни **Authorize** и постави токена от `/api/auth/login`, за да тестваш защитените операции.

## Къде се пазят бизнес правилата

| Правило | Място | Причина |
| --- | --- | --- |
| Ролята е само една от трите допустими | CHECK ограничението в PostgreSQL и JWT удостоверяване | Невалидна роля не може да се запише; клиентът не задава роля в тялото на входа. |
| Само собственикът управлява предмет `InCollection` | API услуга и условието в SQL `UPDATE/DELETE` | Проверява се правото и текущият статус в самата операция. |
| Предложението и двата предмета още са допустими | `TradeService.AcceptTrade` | Една транзакция не допуска частична размяна или две приети предложения за един предмет. |
| Само най-високото наддаване печели; крайният час е задължителен | `TradeService.PlaceBid` и `TradeService.CloseDueAuctions` | Текущата сума се проверява под транзакционно заключване; краят прехвърля собствеността атомарно. |
| Отстъпка от 5% за собствено правило | `TradeService.PlaceBid` | Това е специфично правило на Борис за честно наддаване; връща 409 при недостатъчна стъпка. |
| Контактите се показват само след сделка | Изграждане на `ItemDto` в `CollectionService.Get` | Списъкът и API обектите преди приключване не съдържат телефон или адрес. |
| Съобщенията са достъпни само на участниците | Филтър `SenderId/RecipientId` в `MessageService` | Всеки прочит е ограничен до текущия потребител и другата страна. |
